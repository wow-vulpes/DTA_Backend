# DTA

Сервис проверки комплектности дневных и недельных записей наблюдений.
Реализованы доменные проверки имён, форматов, размеров и комплектности с unit-тестами.
Реализованы POST /api/checks, GET /api/checks и GET /api/checks/{id}, миграция PostgreSQL
и сохранение через JPA. Результаты проверены на PostgreSQL 17.11 через Testcontainers.

## Требования к среде

JDK 21 и доступ к Maven Central при первой загрузке зависимостей.
Maven Wrapper фиксирует Maven 3.9.16; отдельная установка Maven не требуется.
JAVA_HOME должен указывать на JDK 21. Фактическая версия: `./mvnw -version`.

## Компиляция каркаса

```sh
./mvnw compile
```

На Windows используйте `mvnw.cmd compile`.
Компиляция не подтверждает работоспособность бизнес-функций.

## Проверка основы и локальный запуск

```sh
./mvnw '-Dtest=ru.dta.check.domain.*Test' test
```

Эта команда запускает только 111 доменных тестов. Полный тест контекста сохранён
и подключён к PostgreSQL 17.11 через Testcontainers. Миграция V1 создана.
Для проверки хранения запустите Docker, затем:

```sh
./mvnw -B -ntp '-Dtest=CheckPersistenceTest,DtaApplicationTest' test
```

Эта команда запускает 22 тестовых сценария. Testcontainers самостоятельно
поднимает отдельную тестовую БД; .env и ручной запуск PostgreSQL для тестов не нужны.
Первый запуск требует загрузки образа postgres:17.11. Проверяется настоящий PostgreSQL,
не H2. Эти 22 теста успешно выполнены пользователем.
Для приложения потребуются DB_URL, DB_USERNAME, DB_PASSWORD;
секреты в репозиторий не добавляются. Hibernate настроен на validate, не создание схемы.

Unit-тесты дополнительно проверяют распознавание материалов, комплектность daily/weekly,
ошибки и предупреждения, граничные размеры, порядок и неизменяемость результата.

Итоговый запуск приложения и PostgreSQL выполняется через `docker compose up`, без
локальной установки Java/Maven. Compose использует PostgreSQL 17.11 и ждёт healthcheck.

Скопируйте `.env.example` в `.env`, задайте пароль, затем выполните:

```sh
cp .env.example .env
docker compose up --build
```

Приложение будет доступно на `http://localhost:8080`. Остановка: `docker compose down`;
для удаления локальных данных PostgreSQL: `docker compose down -v`.

## Проверки качества

```sh
./mvnw verify
```

Команда проверяет Java 21, стиль основного и тестового Java-кода, запускает тесты,
собирает JAR и создаёт отчёт покрытия `target/site/jacoco/index.html`.
XML-отчёт: `target/site/jacoco/jacoco.xml`. Порог покрытия не установлен.
Покрытие показывает выполненный код, но не доказывает корректность бизнес-правил.
Полный `verify` включает интеграционные тесты и требует доступного Docker.

Checkstyle: 4 пробела, строки до 120 символов (кроме package/import), отсутствие
табуляции, лишних пробелов в конце строк, неиспользуемых и wildcard-импортов;
проверяются базовое именование, пробелы и обязательные фигурные скобки.
Конфигурация — `config/checkstyle/checkstyle.xml`; редактору помогает `.editorconfig`.
Сгенерированные исходники не проверяются на стиль; исключений из JaCoCo нет.

Mockito подключён явным агентом только к JVM тестов, совместно с JaCoCo.
Сообщение JVM об ограничении Class Data Sharing возможно и не означает падение теста.

## Границы решения

По согласованию реализуется Java-версия задания. Извлечение содержимого файлов
не предусмотрено: AI-модель не подключена, API возвращает `extracted: null`.
Сохраняются результаты и метаданные, без постоянного хранения файлов.
Авторизация, версионность дневных записей и скачивание материалов вне объёма.

Внутренние документы требований и прогресса хранятся в рабочем процессе отдельно
и не нужны для запуска приложения.

## POST /api/checks

Multipart-поля: record_type=daily или weekly; повторяемое files (1–20 файлов).
Ответ 201 содержит check_id, status, status_label, reason, issues, documents,
extracted: null и checked_at (UTC). Неполный комплект также сохраняется и возвращает 201.
Содержимое не анализируется и постоянно не хранится; multipart может использовать
временные файлы сервера во время обработки запроса.

Имена: до 255 Unicode-символов, без управляющих символов и разделителей пути.
Бизнес-лимит 20 МиБ: превышение даёт warning и файл не засчитывается в комплект.
Технические лимиты: 25 МиБ на файл, 120 МиБ на запрос вместе с multipart-обрамлением.
Ошибки: 400 повреждённый multipart; 422 поля; 413 размер; 415 Content-Type;
503 недоступность БД; 500 внутренняя ошибка. Тело: code, message, field_errors.

Проверка POST и хранения в контейнерах:

```sh
./mvnw -B -ntp '-Dtest=CheckApiIntegrationTest,CheckPersistenceTest,DtaApplicationTest' test
```

Тесты проверяют настоящий HTTP-сервер, миграции,
сохранение, rollback и лимиты загрузки; крупнейший запрос немного больше 120 МиБ.
Не запускайте Maven через sudo: используйте пользователя с доступом к Docker.

Tomcat дочитывает и отбрасывает до 128 МиБ отклонённого тела (`max-swallow-size`),
чтобы клиент получил HTTP 413 при превышении лимита 120 МиБ около границы.
Это не увеличивает допустимый размер запроса. При значительно больших загрузках
сервер может закрыть соединение, не дочитав всё тело.

## Технологии и причины выбора

- Java 21 — LTS-версия с длительной поддержкой.
- Spring Boot 4.1.1 — HTTP, конфигурация и внедрение компонентов.
- Maven Wrapper — одинаковая версия Maven у разработчиков и в CI.
- PostgreSQL 17.11, Hibernate и Flyway — транзакционное хранение и версионирование схемы.
- Lombok — сокращение шаблонного кода; MapStruct — проверяемое преобразование DTO.
- JUnit, Mockito и Testcontainers — unit-тесты, тесты границ и настоящий PostgreSQL.
- Checkstyle, Enforcer и JaCoCo — стиль, Java 21 и поиск пробелов в тестах.

Процентный порог JaCoCo не установлен: покрытие помогает находить пробелы, но не заменяет
проверку бизнес-правил.

## Архитектура

Один Maven-модуль разделён на логические пакеты:

- `domain` — правила распознавания и комплектности без Spring и JPA;
- `application` — сценарии проверки, транзакции и репозитории;
- `api` — REST, DTO, MapStruct и ошибки;
- `persistence` — JPA-сущности, PostgreSQL и миграции;
- `config` — общие Spring-компоненты.

POST передаёт метаданные файлов в доменную проверку, сервис сохраняет результат одной
транзакцией, API возвращает DTO. GET читает результаты и метаданные; содержимое файлов
не хранится.

## Переменные окружения

| Переменная | Назначение | Пример |
|---|---|---|
| `POSTGRES_DB` | Имя базы в Compose | `dta` |
| `POSTGRES_USER` | Пользователь PostgreSQL | `dta` |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL | локальное значение |
| `DB_URL` | JDBC-адрес приложения | `jdbc:postgresql://db:5432/dta` |
| `DB_USERNAME` | Пользователь приложения | `dta` |
| `DB_PASSWORD` | Пароль приложения | локальное значение |

Создайте `.env` из `.env.example`. Файл `.env` исключён из Git.

## GET /api/checks

Список поддерживает `record_type`, `status`, `from`, `to`, `page` и `size`.
Страницы начинаются с нуля, размер — от 1 до 100. Новые проверки возвращаются первыми.
`GET /api/checks/{id}` возвращает полный результат; отсутствующий UUID даёт 404.
